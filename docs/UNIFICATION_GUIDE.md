# Керівництво з Уніфікації (UNIFICATION GUIDE)

Цей документ описує стандарти, яких ми дотримуємося в проєкті VOLT PREMIUM, щоб код залишався чистим, редагування — зручним, а розгортання — безпомилковим.

## 1. База Даних (Prisma)
- **НЕ ЗМІНЮВАТИ** `provider = "postgresql"` на `sqlite` у `schema.prisma` і не пушити це на GitHub. Сервер Coolify очікує PostgreSQL.
- Якщо ви додаєте нові поля для налаштувань, які існують в єдиному екземплярі на весь сайт (напр., тексти сторінки, контакти), додавайте їх до моделі `PageContent` у `schema.prisma`. 
- Не забувайте додавати `@default("...")` з початковим значенням для нових полів `PageContent`, щоб сайт не був порожнім при чистому розгортанні.
- Після оновлення `schema.prisma` завжди перевіряйте типи локально через `npx tsc --noEmit`.

## 2. Іконки (Lucide React)
- **ТІЛЬКИ `lucide-react`**: Ми не використовуємо `material-symbols-outlined` або кастомні SVG там, де це не критично.
- **В Адмінці**: Всі іконки вибираються виключно через компонент `<IconPicker>`. Ніколи не створюйте звичайні `<input type="text" />` для введення назв іконок вручну.
- **На Клієнті**: Іконки рендеряться динамічно. Якщо компонент отримує назву іконки з бази (напр. `"BadgeCheck"`), він має знаходити її в об'єкті `LucideIcons`:
  ```tsx
  import * as LucideIcons from "lucide-react";
  const IconComp = (LucideIcons as any)[iconName] || LucideIcons.CheckCircle2;
  <IconComp size={24} />
  ```

## 3. Зображення (Image Uploader)
- **В Адмінці**: Всі фотографії та банери завантажуються виключно через компонент `<ImageUploader>`.
- Він автоматично стискає зображення, дозволяє їх обрізати (кроп) та перетворює на оптимізовані WebP. Ніколи не використовуйте стандартні `<input type="file" />` або текстові поля для URL.

## 4. Тексти (Rich Editor)
- **В Адмінці**: Великі текстові блоки, які містять абзаци, жирний шрифт чи списки, повинні використовувати компонент `<RichEditor>` (він же React Quill).
- Не забувайте імпортувати його динамічно, щоб уникнути помилок SSR (Server-Side Rendering):
  ```tsx
  import dynamic from "next/dynamic";
  const RichEditor = dynamic(() => import("@/components/admin/RichEditor"), { ssr: false });
  ```

## 5. Додавання нових сторінок в адмін панель
1. Створіть нову папку з файлом `page.tsx` в `src/app/admin/`.
2. Завжди огортайте вміст сторінки в `<AdminLayout>`.
3. Використовуйте `fetch("/api/content")` для завантаження даних та метод POST туди ж для збереження.
4. Додайте посилання на нову сторінку в `src/components/layout/AdminLayout.tsx` (в ліве навігаційне меню).

## 6. Як правильно пушити
1. Перевірка типів: `npx tsc --noEmit`
2. Перевірка коду: `npm run build` (опціонально)
3. Додати зміни: `git add .`
4. Коміт: `git commit -m "Опис змін"`
5. Відправка: `git push`
6. У Coolify натиснути **Deploy**, якщо автоматичний деплой не налаштовано.
